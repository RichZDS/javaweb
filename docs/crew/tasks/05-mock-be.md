# 05 · 演示数据：后端模拟器（qzd-be-5b1e）

按 `docs/mock-data.md` 第 6 节写模拟器，读 `backend/src/main/resources/mock/`（产品经理在写，先用你自己的 3–5 人小样本开发）。

- 驱动真实业务代码：注册、改资料/目标/设置、上传头像、每日一练、随机/顺序/错题练习（含背题、选项打乱）、提交、结束、收藏（带笔记）、纠错、开考/保存/交卷/超时结算；管理员加题、发布/下架、出卷/上下架、处理纠错、禁用账号。
- 可替换时钟只在 mock 开关打开时生效；定时结算在 mock 运行时关掉，过期考试由模拟器推进时钟后触发结算。
- `last_active_at` 等只在 HTTP 层更新的字段，模拟器要按模拟时间补上，和真实使用一致。
- 防重复：库里有管理员以外的账号就报错退出。密码读 `MOCK_USER_PASSWORD`。
- 预演 `app.mock.dry-run=true`；结束打印汇总。
- 测试：H2 上用 3–5 人、10 天的小样本跑一遍，断言：没有未来时间、没有早于注册的记录、统计接口和表里聚合一致、错题本和作答记录一致、考试分数等于每题得分之和、打卡天数合理。只跑你改到的测试类。
- 本机 MySQL 13306 建库 `quiz_mock`（Flyway + 示例题库 + 管理员），等产品经理 M1 到了用真数据跑预演，再整库跑一遍，把汇总和用时贴进报审。走 heavy 闸门。
- 能在服务器上一次性跑：说明在 `docs/mock-data.md` 末尾补「怎么运行」（本机命令 + docker compose run 命令），jar 里带上 mock 目录。
