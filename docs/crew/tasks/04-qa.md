## 要做

### 第一项：自动化测试工程 `e2e/`（M1，可以在后端完成前先写）
- `e2e/package.json`（独立的 Node 工程，提交 lock 文件），脚本：`test:api`、`test:ui`。
- `e2e/api/`：用 Node 自带的 `node:test` + `fetch`，`BASE_URL` 从环境变量读（默认 `http://localhost:8080`）。按 api.md 覆盖：
  - 注册、登录、令牌过期或缺失 401、`/api/me`。
  - 分类树和进度、搜题、题目详情。
  - 练习：随机抽题不重复、题不够 409 和 `acceptFewer`、提交判分（四种题型，多选少选 0 分）、重复提交只算一次、背题不能提交、进度、结束。
  - 错题：收录、累加、错题练习连对 3 次移出、再错恢复、手动移出。
  - 收藏和笔记。
  - 考试：开考、复用进行中的、版本号保存与旧版本被拒、交卷两次只结算一次、成绩单字段、考试中查题 403。截止相关的用例用管理员接口建一份 1 分钟的试卷来测。
  - 统计：做几道题后各接口数字对得上（作答次数、正确率、章节已做数）。
  - 权限：普通用户访问 `/api/admin/**` 403、看别人的练习 404、禁用账号后登录 403。
  - 管理后台接口：分类、题目、试卷增删改、上下架缺口、纠错处理、Excel 导入（自己生成一个含正确行和错误行的 xlsx）。
  - 每次运行用随机用户名，测试之间互不依赖。
- `e2e/ui/`：Playwright，手机尺寸（iPhone 13）跑 H5 版 App，桌面尺寸跑管理后台。覆盖第一批的主流程：注册 → 选目标考试 → 随机刷题 10 道 → 看结果 → 进错题本 → 重练 → 考一份固定卷 → 看成绩单 → 看统计；后台：登录 → 新建分类 → 新建题目 → 新建试卷并上架。每一步截图存 `/data/crew/qzd-5b1e/shots/qa-<阶段>/`。
- `e2e/scripts/stack.sh`：一键起本地环境（打后端 jar、用临时目录的 H2 起后端、构建并起 H5 和后台的静态服务、等就绪）和关闭环境。所有进程、端口、临时目录在关闭时清理干净。
- `e2e/README.md`：怎么跑。

### 第二项：每个阶段的测试（M2 起持续）
