# 产品验收清单

依据：`docs/spec.md`、`docs/api.md`、`docs/seed-format.md`。P0/P1/P2 分别对应第一、二、三批；三批都要验收。本文定义怎么验收，**不代表任何功能已经通过**。执行人在测试报告中逐项填写：通过 / 不通过 / 未测、所验 commit、设备或浏览器、证据路径；未测必须说明原因。接口证据可由测试同学提供，答辩演示只展示用户可见行为。

## 执行准备

- 准备管理员、普通学员甲、普通学员乙和一个可禁用的测试账号；账号密码不写入报告。两位学员的数据应不同，便于识别串号。
- 三个考试及其章节有已发布题、草稿题、已归档题；准备题量 0、7、至少 20 的练习范围，以及四种题型、大小写敏感和不敏感的填空题、多空题、带图片题、带代码题。管理员创建的临时数据用明确的测试名称，验后清理。
- 准备一份固定卷、一份规则卷及可制造题量不足的规则卷；记录每道题分值和正确答案。预留一份无人考过的卷和一份已经有人考过的卷。
- 时间边界在隔离测试环境用可控时间或提前准备的历史记录复现，不改共享主机时间。短时考试只用测试配置；示例卷仍保持 20–60 分钟。
- 断网用设备网络开关或浏览器离线模式；记录断网、恢复、服务器截止时间。每条独立重置前提，避免上条用例改变统计分母。
- 表内“看到”包括页面和必要的接口检查。API 错误码用于核对口径；界面须有用户能读懂的中文提示。
